Answer one widget's numbers on a route of its own.

A dashboard draws its chrome at once and fills in after, so a request per card is what keeps eight heavy aggregates from holding the whole screen and keeps one card's failure from answering a dashboard with no dashboard on it. Local by construction rather than by a convention somebody has to keep: the route answers about one name, so there is no shape in which it could half answer.

Reachability is checked here and not only where the roster is drawn. A roster that omits a widget is not a protection while the route is still there to be asked, and the answer is nothing found rather than nothing allowed — a 403 would tell a reader that a widget exists and what it is called.

A card's icons and values are worked out by the method that serves it, so the boot had nothing to read: an icon the panel cannot draw, or a value that cannot be sent, is refused here, where it exists, and is that card's failure and no other's.

`PanelWidgetController` and `WidgetAnswer` were already exported from the package index. The file they name was not carried, so the package compiled only where it had been written; a rule in `tooling/` now refuses an import of a file git has never heard of.
