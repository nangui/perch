Report a multipart parser that ignores the upload route's limits. That route refuses a field name carrying brackets by handing the parser a limit, and a parser older than multer 2.2.0 does not refuse the option — it ignores it, so the guard is a no-op, the panel looks exactly as it does when it works, and nothing anywhere says otherwise. `@nestjs/platform-express` pins its parser exactly and the peer range now refuses the versions that pin an old one, so the install this catches is one that got in through an override, which is the only way left in. `perch doctor` reads the version the platform itself resolves to, rather than `./node_modules/multer`, which is nobody's direct dependency and sits nowhere near the root under a store that does not hoist; and it resolves it from the platform's entry point rather than its manifest, because a package whose exports map does not name `package.json` cannot be asked for it and the platform's stopped naming it. An error rather than a warning, warnings not failing the exit code and this being a hole rather than a preference. A version it cannot read, and a project with no platform installed, are both left unremarked: a reading that cannot be made is not a finding. A patch and not a minor, because nothing the command used to accept has changed meaning — the install it now names is one this release already refuses to be installed into.
