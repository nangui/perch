Refuse a field name the parser would pay for. The upload route is the one route whose body is not JSON, and the parser reads a bracket group of digits in a field name as an array index with no ceiling on it: one name claims a length, a second name on the same base walks that length to turn the array into an object, and all of it happens synchronously before the route sees anything. Measured on this repository's own suite: `items[4294967294]` holds the event loop for a hundred seconds and the route then answers 200 as though nothing had happened — and the client's own five-second timeout cannot fire either, because the loop that would fire it is the one being held. The guard against it exists in the parser and is off unless asked for, which is why nothing caught this. The route now asks for it, on both upload routes from one declaration. It refuses names carrying brackets, which the four this route reads — `path`, `state`, `id` and `file` — do not. Depth rather than the newer index limit, because `LIMIT_FIELD_NESTING` is a code the Express adapter maps to 400 while `LIMIT_FIELD_ARRAY_INDEX` is one it does not know, and an error it does not know leaves as a 500; and because depth has been read since multer 2.2.0 where the index limit needs 2.4.0, and an option an older parser does not know is ignored rather than refused. A patch and not a minor: what it stops being accepted was never read.
