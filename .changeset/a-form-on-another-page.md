Refuse a request that changes something and did not come from the panel. A page on another site can make a reader's browser post here, and the browser attaches their cookies, so the request arrives signed in and the host's guards let it through. Measured against this repository's own suite before the guard that stops it: a plain HTML form posting `application/x-www-form-urlencoded` to the save route created a row, and one posting `id=1` to a delete action deleted it, answering `{"processed":1,"refused":0}`. Express parses a form body into the same nested object JSON would have produced, brackets and all, so the route could not tell the two apart, and twenty-four routes write. What a form on another page cannot do is send a content type outside the three a form can send, or set a header of its own, so a request that changes something now has to be `application/json` or carry `x-perch-panel`, which is what the panel's own client sends on the one request it makes that cannot be JSON. A refusal is a 404, the same answer every other refusal here gives, and reading routes are untouched. Nothing is stored and nothing is configured: this package owns no session and no cookie, and what it can read instead is what a browser already refuses to forge. Breaking under the rule that a minor before 1.0 is breaking, and only for a client of your own: one that posts JSON is unaffected, one that posts a file has to add the header. The guide says so, and says what an application on NestJS 12.1 can add in front of it.
