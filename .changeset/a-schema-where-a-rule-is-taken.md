Take a schema from another library where a rule is taken. `.rule()` and `.rules()` now accept anything carrying `~standard`, the property Zod, Valibot and ArkType all have, so a reader who already has a schema passes it instead of unwrapping it by hand. Nothing is installed for it: the specification is a shape, and the two lines of it that are read are spelled in `field.ts`, which keeps the domain's dependency list empty. A schema becomes a rule with no kind, for the reason a function passed there has none: whoever wrote the check wrote the words, and `validationMessages` has nothing to override. The first issue is the one shown, a field holding one error at a time, and a schema that refuses with no message at all is still a refusal. What a schema returns is read as an answer and never as a replacement, so a schema that transforms hands back an output that is dropped; changing a value is what `formatStateUsing` is for, and a check that quietly rewrote what it checked would be a rule that edits the row. This also settles what the documents said: PRD 02 and ARCH 12 named Zod as the engine and nothing ever depended on it, and both now describe the engine that exists, under ADR 0031.
