Name an entry by the path it reads, where it was given no name. `TextEntry.make("family")` drew a value with nothing beside it while `TextInput.make("family")` drew `FAMILY` above the box: the same declaration read two ways, and the difference was not a decision anybody had made. A field falls back to its path and a column falls back to it in its heading; an entry was the one thing that fell back to nothing. Resolved on the server rather than in the renderer, because the wire node of an entry carries no path at all: its value is read on the server and inlined, so the client had nothing to fall back to and would have needed the path shipped for no reason other than to name something. `.label("")` still means no name, an empty string being a name a resource chose rather than the absence of one. Not for `RepeatableEntry`, whose label is the heading of a group rather than the name of a value. Minor, under the rule that a minor before 1.0 is breaking: an infolist that drew no names yesterday draws them today, and an entry deliberately left unnamed has to say `.label("")` to stay that way. It is a small migration but it is one, and a path a resource never meant to show can surface in a page that never showed it.
